# 开发复盘：这个插件是怎么被 BOSS 直聘"教做人"的

这份文档记录 v0.1.0 开发过程中真实踩过的坑、验证过的事实，以及下次做同类插件时应该先做什么。
所有结论都是在真站点上实测得到的，不是文档推测——BOSS 的前端没有任何公开契约，很多行为只能靠试。

## 一、反爬与风控（最花时间的部分）

| 现象 | 实测结论 | 处理方式 |
|---|---|---|
| 打开 DevTools 协议后页面 1 秒内变 `about:blank` | 站点检测到 `Runtime.enable`；其它域（`Page`）不触发 | 只用 `Page` 域，求值走 `Runtime.evaluate` 单次调用，不 `enable` |
| 从 Node 直接请求接口 → `code 37 您的环境存在异常` | 接口校验页面上下文与 `__zp_stoken__` | 所有请求在已登录标签页里用 `fetch` 发出 |
| 首页直接调搜索接口 → `code 37` | 需要搜索页 referer/上下文 | 先导航到 `/web/geek/jobs?...` 再发请求 |
| POST 带 JSON body → 返回 `code 0` 但结果是默认列表 | 接口只认 `application/x-www-form-urlencoded` | 手动拼表单体 |
| 详情接口 → `code 17 缺少必要参数` | 必须带检索结果里的 `securityId` | 检索时把 `securityId` 连同岗位缓存下来 |
| 连续拉详情 → 部分 `code 37`（10 条里挂 3 条） | 频控，和请求间隔有关 | 3 次重试 + 退避（1.5s / 2.8s），第 3 次先导航到详情页再取；实测 10/10、12/12 成功 |
| 复用的标签页打开详情 → 被弹回 `/guangzhou/?seoRefer=index` | 站点对"老标签页 + 直接跳详情"会重定向 | 每次操作新开标签页，用完关掉（顺带解决窗口堆积） |
| 详情页 URL 少了 `securityId` | 页面照常渲染，但「立即沟通」点了没反应 | 拼 URL 时强制带 `securityId`（缺失就直接报错，不猜） |

## 二、打招呼流程（DOM 驱动的三个坑）

1. **首次联系不会跳转**：给没聊过的 HR 点「立即沟通」，站点只创建会话，页面停在详情页；等会话建好后按钮变成「继续沟通」，再点才会进聊天页。
   → 实现成"点完等 8 秒，没跳转就重开详情页再点一次"，两次调用变成一次。
2. **发送按钮是禁用态**：输入框为空时 `button.btn-send` 带 `disabled` 类，先点后填会被吞掉。
   → 先写入文本，等按钮去掉 `disabled` 再点，最后用"输入框是否清空 + 聊天区是否出现文案"双向校验；没发出去补一次回车。
3. **系统会先发一句自己的招呼语**：点「立即沟通」时 BOSS 自动发送"您好，可以和您聊聊吗？"，我们的介绍紧随其后。这不是 bug，但要在文档里说清楚，否则用户会以为插件乱发消息。

## 三、匹配分数（容易被误读的地方）

分数只衡量"简历文本 vs JD 文本"的重合度，**不含薪资、职级、公司质量**。实测后果：

- 一个 10 年经验的运维，投「硬件运维工程师（10-12K）」拿到 100 分；
- 投「k8s 运维工程师（23-25K）」只有 82 分。

所以加了两个硬性风险提示，而不是去调分数：
- 命中「驻外/海外/马来西亚…」→ 标记 `overseas` 并置顶风险；
- 薪资上限 ≤12K 且经验 ≥8 年 → 提示"薪资和期望可能不匹配"。

结论：**分数用来排序和筛掉不相关的岗位，不用来决定"这个岗位值不值得投"**，后者要看薪资和风险提示。

## 四、工程与协作教训

- **改代码必须真重启**：热加载对 Host 插件无效。每次改完要确认进程启动时间变了，否则会以为是代码没生效。本轮因为这点白重启了 4 次。
- **重启前先把能本地验的都验完**：用 `send:false` 跑完整链路、只读检查 DOM 结构、单测覆盖纯函数——这样每次重启的"信息增量"才最大。
- **PowerShell 会毁掉中文源文件**：`Set-Content` 写 UTF-8 中文会产生 U+FFFD 和非法字节，测试文件就是这么废掉重写的。中文源码一律用文件写入工具，不要走 shell 字符串。
- **工具返回值必须是无损 JSON**：宿主会拒绝含 `undefined`/`NaN` 的输出（`value is not lossless JSON`），所以所有返回都过一层 `jsonSafe`。
- **缓存要能自洽**：`boss_match_jobs` 走 `job_ids` 时分数比走关键词低 2 分，原因是前者只能从缓存拿到部分字段。修法是检索时把 `skills/labels/hrOnline` 一并落盘，两条路径共用同一份数据。
- **不要向下覆盖好数据**：详情接口不返回 `hrOnline`，合并时用空值覆盖会把「在线」错写成「离线」。规则：空值不覆盖、`true` 不被降级。

## 五、如果重做一次

1. 先花 20 分钟把站点的关键接口和 DOM 探明（用 `boss_browser eval` 只读探测），再写代码，而不是边写边猜。
2. 第一天就把"新标签页 + 关闭标签页"的模式定下来，别用复用标签页的方式折腾。
3. 纯逻辑（简历解析、打分、文案、配置）先写测试，DOM 部分留一个 `send:false` 的联调脚本。
4. 文档里把"站点会自己发招呼语""分数不代表值得投"这两条写在最前面，能省掉大量解释。
